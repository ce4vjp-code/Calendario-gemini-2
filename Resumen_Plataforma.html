Plataforma de Gestión de Evaluaciones

Documentación Técnica, Funcional y Auditoría de Seguridad

1. Propósito de Diseño

El sistema fue concebido como una solución web centralizada y altamente responsiva para la organización académica de un liceo. Su objetivo principal es permitir a los docentes programar, visualizar y coordinar fechas de evaluaciones (pruebas, disertaciones, trabajos prácticos) de manera transparente, evitando la superposición de fechas para los estudiantes.

Su interfaz utiliza un enfoque Mobile-First de diseño minimalista, presentando la información en formato de "Lista" para garantizar la legibilidad en pantallas pequeñas, pero conservando la capacidad de exportar cuadrículas panorámicas tradicionales.

2. Funcionalidades Principales

  • Interfaz Híbrida Adaptativa: Sistema de lectura basado en listas interactivas en pantalla, que transmuta mediante reglas CSS (@media print) a una clásica cuadrícula mensual tipo Google Calendar exclusivamente al momento de exportar o imprimir.
  • Gestión Académica (CRUD): Los profesores autenticados pueden crear, editar, visualizar y eliminar sus propias evaluaciones escolares, asignándoles horarios, cursos, asignaturas y colores categorizados según el tipo de evaluación.
  • Panel de Administración: Un centro de control exclusivo que permite la gestión del cuerpo docente, incluyendo la generación de invitaciones de un solo uso, restablecimiento de contraseñas y eliminación de usuarios (lo que desencadena una eliminación en cascada de sus evaluaciones).
  • Autenticación Geolocalizada: Inicio de sesión y registro diseñados específicamente para el estándar nacional, utilizando el RUT chileno como identificador único principal.

3. Arquitectura y Métodos de Seguridad (Backend)

El sistema está construido sobre una arquitectura LAMP (Linux, Apache, MySQL, PHP) pura, utilizando una API RESTful interna que se comunica de forma asíncrona con el frontend vía JavaScript. Tras la reciente auditoría, el sistema cuenta con las siguientes capas de seguridad:

  • Prevención de Inyección SQL Sentencias Preparadas (PDO): Todas las interacciones con la base de datos utilizan Prepared Statements con parámetros enlazados. Esto anula por completo la posibilidad de ataques por inyección de código SQL.
  • Cifrado BCRYPT Protección de Credenciales: Las contraseñas de los usuarios jamás se almacenan en texto plano. Se procesan a través del algoritmo password_hash() de PHP, haciéndolas indescifrables en caso de vulneración de la base de datos.
  • Mitigación IDOR Control de Acceso Directo a Objetos: Los scripts de edición y eliminación validan obligatoriamente la propiedad del objeto antes de ejecutar una acción. El servidor verifica que la evaluación pertenezca a la sesión activa (o a un Administrador), bloqueando el resto con códigos HTTP 403.
  • Anti-Suplantación Forzado de Identidad de Autor: En la creación de registros, el backend desestima cualquier información de autoría proveniente del navegador, inyectando directamente el nombre alojado de forma inmutable en la sesión segura del servidor ($_SESSION).
  • Doble Capa de Verificación Algoritmo Módulo 11 (RUT): La integridad de la identidad se valida mediante el dígito verificador del RUT. Este cálculo se realiza en el cliente (Frontend, para velocidad y usabilidad) y en el servidor (PHP, como barrera de seguridad inviolable).
  • Gestión CORS Restricción de Origen: Se instruye a los navegadores a bloquear cualquier intento de comunicación con la base de datos que provenga de un dominio web externo o no autorizado.
