Ecosistema: Calendario de Evaluaciones del Liceo TPGGM

Este documento detalla la arquitectura, componentes y medidas de seguridad implementadas en la plataforma "Calendario de Evaluaciones". El ecosistema está compuesto por un robusto backend centralizado que alimenta tanto a la interfaz web como a dos aplicaciones móviles nativas (una para profesores y otra para la administración).

1. Arquitectura Central (Backend y API)

El corazón del ecosistema se encuentra en el servidor web de producción (new.liceotpggm.cl/evaluaciones/), desarrollado en PHP y apoyado por una base de datos relacional (MySQL/MariaDB).

Gestión de Accesos y Autenticación

  • Control de Roles: Existen dos perfiles estrictos en la base de datos: admin (Administrador) y profesor (Usuario estándar). La API de PHP verifica activamente la variable de sesión $_SESSION['user_rol'] en cada solicitud.
  • Sistema de Códigos de Invitación: El registro de nuevos profesores está cerrado al público. Para crear una cuenta, un profesor necesita ingresar un código único alfanumérico (ej: PROFE-XXXXX) autogenerado y emitido por el administrador. Estos códigos son de un solo uso.
  • Autenticación en Dos Pasos (2FA): Para el rol de Administrador, el sistema exige un código dinámico de 6 dígitos enviado por correo electrónico tras validar correctamente la contraseña, evitando el ingreso mediante credenciales filtradas.

Seguridad del Lado del Servidor (PHP)

  • Consultas Preparadas (PDO): Todas las interacciones con la base de datos (inserción de usuarios, registro de logs, etc.) utilizan sentencias preparadas de PDO (prepare/execute), mitigando al 100% el riesgo de inyecciones SQL.
  • Encriptación de Contraseñas: Las claves de acceso de todos los usuarios se almacenan utilizando password_hash() con el robusto algoritmo de encriptación unidireccional BCRYPT.
  • Registro de Auditoría (Logs): Se mantiene un registro inmutable en base de datos de cada inicio de sesión (exitoso o fallido, registrando IP y dispositivo) y de cada actividad administrativa (eliminación de usuarios, cambios de claves, envío de invitaciones).

2. Plataforma Web

La versión de escritorio (Web) es la interfaz clásica que permite interactuar con el backend de manera directa a través del navegador.

Portal Administrativo (admin.html)

  • Interfaz Protegida: Un script inicial de validación consulta al backend (check_session.php). Si no hay una sesión activa de administrador, expulsa inmediatamente al usuario hacia la página de login.
  • Gestión de Usuarios: Permite visualizar en una tabla a todos los profesores registrados. Incluye funciones para:
    • Modificar correos electrónicos.
    • Resetear y reenviar contraseñas automáticamente vía SMTP.
    • Eliminar cuentas (con doble confirmación).
  • Módulo de Auditoría y Logs: Visualización del historial completo de ingresos y movimientos del sistema filtrados por fecha.
  • Generador de Invitaciones: Permite emitir y despachar por correo los códigos PROFE-XXXXX.

3. Aplicación Nativa para Profesores (AppAndroid)

Aplicación enfocada en el usuario final, diseñada para ser rápida, ligera y de fácil distribución.

  • Tecnología: App de Android en Kotlin utilizando un esquema de WebView optimizado, lo que permite aprovechar la inmediatez de carga de las vistas móviles del servidor y asegura que todos los profesores vean siempre la versión más actualizada sin necesidad de actualizar la aplicación desde la tienda.
  • Seguridad y Accesos: Impide el acceso a vistas administrativas y descansa sobre la protección de sesión por Cookies del backend.

4. Aplicación Nativa de Administración (AppAndroidAdminNativa)

La "joya de la corona" del ecosistema. Es una aplicación Android 100% nativa (sin WebView), diseñada exclusivamente para el control total del Liceo desde el dispositivo del Administrador.

Tecnologías y Componentes

  • Arquitectura UI: Construida con XML y Material Design Components. Emplea AndroidX Navigation y un BottomNavigationView para intercambiar fluidamente entre Fragmentos (Usuarios, Auditoría, Códigos).
  • Conectividad: Utiliza la librería Retrofit y Coroutines (procesamiento asíncrono en hilos de fondo) para enviar peticiones HTTP y mapear el JSON devuelto por el servidor PHP hacia modelos de datos de Kotlin (Data Classes).

Módulos Nativos

  • Dashboard de Usuarios (UsersFragment): Lista en tarjetas a los usuarios utilizando un RecyclerView. Permite, con cuadros de diálogo nativos (AlertDialogs), la eliminación segura de usuarios, reseteo de claves y edición de correos.
  • Auditoría (AuditFragment): Con un calendario interactivo (DatePickerDialog), extrae y unifica los eventos de actividad y login en una línea de tiempo cromática.
  • Invitaciones (InviteFragment): Pantalla limpia para gatillar el despacho de códigos de invitación desde el celular.

Seguridad en Capa Nativa

  • Doble Validación de Rol: En la actividad de Login, la App parsea la respuesta del servidor. Si el usuario logueado exitosamente resulta ser un "profesor", la aplicación bloquea el acceso localmente y cierra la sesión, reservando el paso exclusivamente al rol "admin".
  • Persistencia de Sesión Encriptada: Para ofrecer una excelente experiencia de usuario (UX) sin sacrificar seguridad, la "Cookie" (PHPSESSID) entregada por el servidor se almacena de forma persistente utilizando la memoria segura del dispositivo (SharedPreferences). De esta forma, la app puede pasar a segundo plano sin perder la sesión.
  • Interceptor y Auto-Logout Global: Se programó un interceptor de red HTTP (OkHttp Interceptor). Si el servidor envía un error 403 (Acceso Denegado) en cualquier momento (por ejemplo, si la sesión caducó en el servidor de producción o alguien la revocó), la aplicación intercepta esto, destruye el almacenamiento de cookies local y fuerza al administrador de vuelta a la pantalla de Login con una alerta de seguridad.
